# 8 · 从源码到可交付产物

前置：[验证与扩展方法](07-testing.md)。阅读[package.json](../../package.json)的scripts与build字段，再读[开发指南](../DEVELOPMENT.md)及[贡献规范](../../CONTRIBUTING.md)。

`npm ci`按锁文件安装依赖；`npm run verify`验证源码；`npm run pack`生成可运行目录；`npm run build`生成安装包。验证通过不等于发布成功，构建也不等于用户已经获得新版。版本、更新记录、远端标签、发布附件需在正式发布流程中相互对应。

教学材料位于`docs/learning`与`lessons`，打包范围仍是src、CHANGELOG和package.json，因此实验不会改变日历界面或增加运行时依赖。扩展方法从ES模块、函数式转换到事件订阅逐层出现；只有职责清晰且确有用途的部分进入应用。

练习：在自己的开发副本运行验证，检查构建配置会包含哪些文件，再说明源码测试与安装包冒烟为什么都需要。不要为了完成阅读练习推送标签或触发发布。

完成检查：能追踪一次点击，说明数据边界，重放状态动作，用假依赖测试失败路径，并区分源码、构建产物和发布版本。后续可以选择一个小功能，把设计、实现、测试和文档连接起来，不必一次引入更多框架。
