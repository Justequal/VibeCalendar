# VibeCalendar v1.1.22 优化与验证报告

日期：2026-09-06。基线：cfd55ef / v1.1.21。此前报告列出的代码优化项已落实，版本更新为1.1.22。

## 已完成的优化

| 领域 | 最终行为 |
| --- | --- |
| 长期运行 | 跨午夜和窗口恢复时更新今天与时钟，保留当前浏览位置 |
| 渲染 | 视图与只读节假日数据引用不变时跳过网格替换，重复点击今天不会重建42格 |
| 日期范围 | 正确支持1–9999年，避免1–99年映射到1900年代；极端滚动钳制在边界，越界相邻格禁用 |
| 节日本日 | 使用香港天文台1901–2100年历表中的春节、清明、端午、中秋日期，替换近似公式与运行时农历推算；范围外停止推算 |
| 缓存补全 | 双提供方成功保留30天，单提供方与降级数据六小时后重试；恢复联网时立即重试可见的非完整数据 |
| 内存 | 最近访问缓存及未命中记录分别最多12年；离线沿用数据保留映射引用 |
| 磁盘 | 节假日缓存最多24年，清理只处理节假日命名空间，保留偏好和其他数据 |
| 网络 | 最多同时处理两个年份，最近四个任务等待；超限旧任务使用已有数据完成，最新浏览优先 |
| 请求取消 | 主数据镜像通过校验后取消另一镜像，包括慢响应体；独立提供方继续合并 |
| 输入与验证 | 公告打开后抑制排队滚动，Ctrl滚轮不翻页；年度记录数、名称长度和持久化内容大小均有限制 |
| 发布验证 | 界面测试支持源码和打包资源，Windows构建及正式发布工作流均增加真实Electron检查 |

## 数据来源与核对

- 本日日期来自[香港天文台公历与农历对照表](https://www.hko.gov.hk/en/gts/time/conversion.htm)，同步脚本逐年下载文本表并要求每年四个节日齐全。已处理旧表大小写和重复闰月，确保不会把端午移到闰月。
- 2026年放假、补班样本取自[国务院办公厅通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，通过[北京市政府转载](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)核对。联网测试逐项核对39个特殊日期，双源合并结果全部匹配。
- 官方天文表范围为1901–2100年，天文台提示远期日期可能随计算修订；该表也不代表所有年份的法定调休安排。其他年份调休仍来自远程提供方与缓存。

## 本机性能采样

环境：Windows，Electron44.0.0，340×500隐藏测试窗口，关闭硬件加速。结果是本机采样，不是跨设备保证。

| 指标 | 结果 |
| --- | --- |
| 1000次缓存往返导航 | 341毫秒，1000次网格替换 |
| 重复点击今天 | 0次网格替换，保持原节点 |
| 入口脚本计时至页面加载完成 | 本次约230毫秒；另一轮约935毫秒，不能当作完整冷启动指标 |
| 30秒空闲采样 | 各进程CPU用量合计约0.055% |
| 进程工作集合计 | 约342MiB，包含共享页重复计算，不等于独占物理内存 |
| 导航前后JS堆 | 约1.82MiB到2.39MiB，未强制GC，不据此声称无长期泄漏 |

原路径在每次缓存操作同步和异步阶段各替换一次网格；当前仅内容变化时替换。可确认的是减少重复DOM工作，不把它等同于整机性能提高50%。

## 复现命令

- npm run verify：语法与单元测试。
- npm run test:ui：真实界面测试；VIBE_TEST_APP_ROOT可指向resources/app.asar，VIBE_TEST_SCALE可设显示比例。
- npm run test:holiday-network：实时数据对照官方2026年样本。
- npm run test:update-network：真实更新版本查询。
- npm run test:performance：1000次导航及30秒空闲采样；VIBE_PERFORMANCE_REPORT可指定JSON输出。
- npm run sync:festivals：更新官方本日表，失败年份可利用临时缓存继续重试。
- npm run build -- --publish never：生成安装包与更新元数据。
