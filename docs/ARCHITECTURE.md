# Vibe Calendar 架构说明

## 1. 设计目标

项目功能简单，但代码按清晰边界组织：日期计算可测试、界面不依赖网络首屏、渲染进程不持有 Node.js 权限，后续增加事件、主题或设置时不需要推翻现有结构。

## 2. 分层

```text
Electron 主进程
  ├─ 创建和管理 BrowserWindow
  ├─ 限制导航、弹窗与渲染权限
  └─ 在满足条件时检查应用更新
             │
             ▼
渲染进程
  ├─ calendar-core.js：日期领域层，无 DOM、网络或存储依赖
  ├─ holidays.js：数据层，负责请求、合并、缓存和降级
  └─ renderer.js：表现层，负责状态、DOM 与用户事件
```

### `src/main/main.js`

主进程入口。它创建深色无边框窗口，启用上下文隔离和沙箱，并阻止非预期导航与新窗口。当前版本还会短暂置顶窗口以确保启动可见，并关闭 GPU 硬件加速以兼容部分 Windows 显卡环境。

不要把日期计算、网络请求或 DOM 逻辑放进主进程。只有必须访问操作系统的能力才属于这一层。

### `src/main/updater.js`

独立封装 `electron-updater`。开发模式或 GitHub 仓库尚未配置时直接跳过，更新失败只记录日志，不影响日历功能。

### `src/renderer/calendar-core.js`

日期领域层，所有导出均为纯函数：

- `startOfMonth`：把日期规范为所在月 1 日
- `addMonths`：安全翻月，避免月底溢出
- `buildMonthCells`：生成固定 42 个日期单元格
- `toDateKey`：生成节假日索引键
- `getWeekdayLabels` / `getMonthLabel`：生成显示文本

该文件同时支持浏览器全局对象和 CommonJS，仅为了让 Node.js 内置测试运行器可以直接加载。这里不应访问 `document`、`localStorage` 或 `fetch`。

### `src/renderer/holidays.js`

节假日数据层具有四级策略：

1. 当前进程内存缓存
2. 未过期的 `localStorage` 缓存
3. 两个独立远程提供方
4. 过期缓存或固定公历日期兜底

NateScarlet 的 CDN 与 Raw URL 是同一数据集的镜像，通过 `Promise.any` 选取第一个成功响应，只算一个提供方。远程请求通过 `AbortController` 在 5 秒后取消。

同一年请求存入 `pendingRequests`，避免快速翻月时重复请求。远程缓存有效期 30 天，降级缓存 6 小时后允许重试。

### `src/renderer/renderer.js`

表现层维护三个状态：

- 当前展示月份
- 一周是否从周一开始
- 当前渲染版本号

每次刷新先同步绘制缓存数据，再异步获取节假日。异步完成后只有版本号仍然一致才会重绘，因此旧月份的慢请求不会覆盖用户刚切换的新月份。

## 3. 启动与数据流

```text
app ready
  → 创建安全 BrowserWindow
  → 加载本地 HTML/CSS/JS
  → 使用本地缓存立即生成 42 格月历
  → 后台并发刷新当前年份节假日
  → 请求仍对应当前月份时更新节假日标记
```

跨年月份会同时加载相邻年份，以保证网格中上月或下月日期的节假日标记正确。

## 4. 安全模型

渲染进程配置：

- `nodeIntegration: false`
- `contextIsolation: true`
- `sandbox: true`
- `webSecurity: true`

页面 CSP 将脚本和样式限制为本地资源，只允许连接明确列出的节假日数据域名。主窗口禁止导航和创建新窗口。

关闭硬件加速会牺牲少量合成性能；如果以后恢复透明效果或加入复杂动画，应在目标设备上验证 GPU 稳定性后再决定是否按平台启用。

如果新增托盘、文件读写、通知等系统功能，应增加 preload 文件，并使用 `contextBridge` 暴露单一用途的方法。不要向页面暴露原始 `ipcRenderer`，也不要为了方便关闭隔离。

## 5. 测试策略

当前单元测试覆盖：

- 月底翻月不溢出
- 跨年翻月
- 42 格网格和相邻月份日期
- 周一首日排列
- 日期键补零

新增日期规则时优先在 `calendar-core.js` 写纯函数并补边界测试。节假日服务后续可进一步注入 `fetch` 和存储适配器，以便测试超时、数据冲突与降级路径。

## 6. 扩展约定

### 新增设置

小型纯前端偏好可以沿用带命名空间的 `localStorage` 键。涉及隐私、账户或跨设备同步时，应设计独立设置服务，不要散落在事件处理函数中。

### 新增节假日提供方

先把外部格式标准化为：

```js
{
  '2026-10-01': { name: '国庆节', isHoliday: true }
}
```

然后加入提供方合并逻辑，并同步更新 CSP。镜像地址不能当成独立数据源。

### 新增日历事件

建议新增独立的 `events.js` 数据层，不要把事件持久化逻辑写入 `renderer.js`。日期格只接收已经标准化的展示数据。
