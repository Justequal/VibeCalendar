# VibeCalendar 架构说明

本文描述当前代码的职责边界、主要数据流和扩展约定。它是维护者理解项目结构的入口；具体命令见 [开发指南](DEVELOPMENT.md)，正式发布见 [发布指南](RELEASING.md)。

## 1. 设计原则

项目保持无前端框架、无打包器的轻量结构，但不把所有逻辑堆叠在一个脚本中：

- **系统能力集中在主进程**：窗口、IPC、文件监听和安装更新不进入渲染层。
- **桥接能力最小化**：Preload 只暴露页面真正需要的版本、检查和更新状态接口。
- **领域计算保持纯净**：日期计算不访问 DOM、网络和存储，可直接在 Node.js 中测试。
- **首屏不依赖网络**：先绘制日期和已有缓存，再异步刷新节假日。
- **功能按控制器拆分**：日历交互与更新交互分别维护，翻译文案集中管理。
- **失败可降级**：节假日或更新服务故障不能阻止基础日历使用。
- **优化以可读性为前提**：优先消除重复请求、重复存储读取和无意义重绘，不引入与当前规模不匹配的抽象。

## 2. 运行时分层

```text
┌──────────────────────── Electron 主进程 ────────────────────────┐
│ main.js                                                         │
│  窗口生命周期 · 安全限制 · IPC 注册 · 开发时文件监听             │
│       │                                                         │
│       └── updater.js                                            │
│           GitHub Release 查询 · 版本比较 · electron-updater     │
└──────────────────────────────┬──────────────────────────────────┘
                               │ ipcRenderer.invoke
┌──────────────────────────────▼──────────────────────────────────┐
│ preload.js：window.appUpdates 的最小只读桥接                     │
└──────────────────────────────┬──────────────────────────────────┘
                               │
┌────────────────────────── 渲染进程 ─────────────────────────────┐
│ calendar-core.js     纯日期计算与节日本日判定                    │
│ interaction-core.js  滚轮单位换算与完整行累计                    │
│ holidays.js          节假日请求、标准化、缓存、合并与降级         │
│ translations.js      中英文用户界面文案                          │
│ update-controller.js 版本号、手动检查与公告弹层                  │
│ renderer.js          页面状态、日期网格渲染与日历输入事件         │
│ index.html/style.css  安全页面骨架与视觉系统                      │
└─────────────────────────────────────────────────────────────────┘
```

脚本由 `index.html` 按依赖顺序加载：`calendar-core.js` → `interaction-core.js` → `translations.js` →
`holidays.js` → `update-controller.js` → `renderer.js`。项目没有模块打包步骤，因此调整文件名、
新增全局入口或改变加载顺序时，必须同步检查 `index.html`。

## 3. 模块职责

### `src/main/main.js`

主进程入口负责：

- 创建 340 × 500 的深色无边框固定尺寸窗口；
- 配置上下文隔离、沙箱、Web 安全策略和 Preload；
- 禁止页面导航及创建新窗口；
- 注册版本与更新相关 IPC；
- 在 `--live-preview` 模式监听 `src/renderer`，合并短时间内的文件事件后刷新窗口；
- 正式应用启动时发起静默更新检查。

它不处理日期、节假日格式或 DOM。只有需要 Electron 或操作系统权限的逻辑才应放在这里。

### `src/main/preload.js`

Preload 通过 `contextBridge` 暴露冻结的 `window.appUpdates`：

| 方法 | 作用 |
| --- | --- |
| `getVersion()` | 读取当前运行应用的版本号 |
| `getCurrentRelease()` | 读取安装包内当前版本对应的维护说明 |
| `checkForUpdates()` | 触发一次用户主动的更新检查 |

页面不会获得原始 `ipcRenderer`，也不能直接调用 Node.js API。新增系统能力时，应继续采用“一个明确动作对应一个桥接方法”的方式，而不是扩大通用权限。

### `src/main/updater.js`

更新服务把用户可见的手动检查统一为三种结论：`available`、`up-to-date` 或 `error`。
`development` 和 `skipped` 只用于不展示结果的启动路径。

- 安装版使用 `electron-updater` 直接读取 `latest.yml`；发现新版后立即启动差分下载。
- GitHub Release API 只供开发预览查询版本，避免正式安装版因 API 限流出现“发现新版但没有下载”的分裂状态。
- 更新器通过受控的 `updates:status` 事件发送下载状态；渲染层用更新按钮的背景填充和百分比表示下载进度。
- 手动检查在发现新版后立即返回结构化结果，`electron-updater` 独立在后台继续，下载器无响应不会阻塞按钮反馈。
- 开发版启动时跳过更新网络访问，手动检查只比较版本，不下载或安装。
- 最新版本查询设置 10 秒超时，并复用并发请求；成功结果缓存 5 分钟。手动检查会强制刷新，避免用缓存判断是否有新版本。
- Release 字段会限长，外部链接只接受 GitHub 的 HTTPS 地址；网络失败转为可展示的错误结果。
- 安装包更新检查会合并并发调用，同一版本只启动一次下载，下载完成事件也只保留一个可安装状态。
- 主进程保存最近的更新状态，窗口加载后主动读取，避免错过早于渲染层订阅发生的下载事件。
- 版本比较由服务层完成，支持可选的 `v` 前缀、预发布标识和构建元数据，渲染层不解析版本字符串。

### `src/renderer/calendar-core.js`

日期领域层导出纯函数，主要包括：

- `startOfMonth`、`addMonths`、`addDays`：规范日期并安全跨月、跨年；
- `buildMonthCells`、`buildWeekWindowCells`：生成连续的 42 个日期单元格；
- `getWeekdayLabels`、`getMonthLabel`：生成中英文标题；
- `toDateKey`：生成 `YYYY-MM-DD` 索引键；
- `getChineseHolidayKey`、`getChineseFestivalKey`：把数据源名称映射为稳定键，并判断真正的节日本日。

文件使用 UMD 形式，同时支持浏览器全局 `CalendarCore` 和 CommonJS 测试。该层不应读取
`document`、`localStorage` 或 `fetch`。

42 格窗口使用单个正午 `Date` 游标连续推进，减少临时对象并避开部分时区的夏令时午夜边界。中国农历 `Intl.DateTimeFormat` 会惰性创建并复用；运行环境不支持该日历或格式化失败时，公历日期和假期仍照常显示，只是不标注无法确认的农历节日本日。

### `src/renderer/interaction-core.js`

输入领域层把像素、行和页面三种滚轮单位统一换算为日历行数，并持续保留不足一行的余量。快速输入可以一次返回多行，渲染层再把同一动画帧内的结果合并为一次 DOM 更新。该模块同时导出 CommonJS 接口，回归测试会明确断言大幅滚动不会退化为只移动一行。

### `src/renderer/holidays.js`

节假日数据层把不同提供方统一为以下结构：

```js
{
  '2026-10-01': {
    name: '国庆节',
    isHoliday: true,
    holiday: 'nationalDay',
    festival: 'nationalDay'
  }
}
```

其中 `holiday` 表示该记录所属的法定假期，`festival` 只在真正的节日本日存在。因此同一假期内的普通休息日不会被误标为节日本日。

数据获取顺序是：

1. 当前进程内存缓存；
2. 未过期的 `localStorage` 缓存；
3. NateScarlet 主数据与 Timor 补充数据；
4. 过期缓存；
5. 元旦、劳动节、国庆节三个固定公历日期的最小兜底。

NateScarlet 的 jsDelivr 与 GitHub Raw 地址只是同一数据集的镜像，通过首个成功结果提高可用性，但只算一个独立提供方。主、辅提供方冲突时保留主数据并输出诊断信息。

该层负责校验年份、真实日期、名称、布尔字段和持久化缓存结构，损坏缓存会被移除。同一年只保留一个在途请求；没有持久化数据的年份也会记录一次“未命中”，避免每个日期格重复读取 `localStorage`。共享映射和记录被冻结，防止渲染层意外修改；内存最多保留 12 个年份，并可在淘汰后从持久化缓存恢复。远程数据缓存 30 天，降级结果 6 小时后允许重新尝试网络。

服务以 UMD 形式导出 `HolidayManager` 和标准化辅助函数。测试可以注入 `fetch`、存储、时钟和日志；浏览器仍只需使用稳定的 `window.holidayManager.getHolidays()` 与 `fetchHolidays()` 接口。

### `src/renderer/translations.js`

所有用户可见的中英文界面文案集中在 `VibeCalendarTranslations`。日期格内的英文节日使用短标签，完整英文名称保留在图例、悬停提示和无障碍文本中。

当前版本说明属于维护者编写的发布内容，不做自动翻译；弹层标题、加载态和错误提示会随界面语言切换。

### `src/renderer/update-controller.js`

更新界面控制器只负责：

- 显示当前版本号；
- 打开、关闭当前安装版本说明；
- 发起手动检查并显示状态提示；
- 订阅后台更新事件并维护按钮背景下载进度；
- 防止用户在一次检查未完成时重复触发；
- 在语言切换时同步更新按钮和无障碍文案。

当前版本说明通过 `textContent` 写入，绝不作为 HTML 执行。弹层关闭后焦点返回版本按钮；弹层打开时日历快捷键不会误触发。

### `src/renderer/renderer.js`

日历表现层维护四项核心状态：当前可见日期、一周首日、语言和异步渲染版本号。它负责日期网格、图例、偏好持久化、时钟和输入事件，不再实现更新流程。

日期格通过 `DocumentFragment` 一次替换；滚轮输入先换算为星期行数，保留不足一行的余量，并把同一动画帧内的多次输入合并为一次渲染。这样既保留快速滚动的实际幅度，也避免高频事件触发重复 DOM 更新。

## 4. 主要数据流

### 日历启动与刷新

```text
页面加载
  → 读取语言与周首日偏好
  → 从内存/本地缓存同步取得节假日
  → 立即生成 42 格日期与图例
  → 并发刷新当前窗口涉及的年份
  → 请求仍对应当前渲染版本时重新绘制
```

42 格窗口可能跨年，因此渲染层会提取所有可见年份并并发加载。`renderVersion` 保证较早月份的慢请求不会覆盖用户后来切换到的月份。

### 更新检查

```text
更新按钮或启动检查
  → renderer/update-controller
  → window.appUpdates
  → preload IPC
  → main/updater
      ├─ 手动检查：GitHub Releases API → 比较版本
      │   └─ 安装版发现新版：electron-updater → latest.yml → 后台下载
      └─ 安装版启动检查：electron-updater → latest.yml → 后台下载
  → 返回结构化状态并更新界面
```

点击版本号读取打包在应用中的 `CHANGELOG.md` 当前版本段落，不访问网络，也不触发安装。安装版手动“检查更新”直接读取远端更新清单，发现新版后立即启动后台下载；开发预览只查询 Release 信息而不下载。

### 实时预览

`npm run dev` 添加 `--live-preview` 参数。主进程只监听 `src/renderer` 下的 HTML、CSS、
JavaScript 和 JSON 文件，并在约 100 毫秒内合并连续保存事件后调用无缓存刷新。监听器与窗口生命周期绑定，窗口关闭时会自动释放。

## 5. 性能与可靠性约束

- **同步首屏**：网络请求不位于首次绘制的关键路径。
- **请求复用**：同一年节假日请求和同一次更新检查不会并发重复执行。
- **缓存分层**：内存缓存避免渲染热路径上的持久化读取，`localStorage` 支持跨启动复用。
- **异步防竞态**：渲染版本号丢弃过期响应，失败路径总会释放在途状态。
- **批量 DOM 更新**：日期格通过片段一次写入，滚轮事件按动画帧合并。
- **可恢复降级**：远程服务、存储或更新查询失败均保留基本日历功能，并允许稍后重试。

优化时先通过测试或可复现步骤确认瓶颈。不要为了减少少量函数调用而破坏领域边界，也不要把远程数据当作可信输入跳过校验。

## 6. 安全模型

BrowserWindow 保持以下设置：

- `nodeIntegration: false`
- `contextIsolation: true`
- `sandbox: true`
- `webSecurity: true`

页面 CSP 将脚本、样式和图片限制为本地资源，只允许连接明确列出的节假日数据域名。GitHub Release 请求发生在主进程，不需要扩大渲染进程的 `connect-src`。主窗口同时禁止导航和创建新窗口。

更新 IPC 还会核对调用者是否来自应用本地的 `index.html`。这是一层纵深防御：即便将来页面结构变化，也不应仅依赖“当前窗口不会导航”这一假设来授权系统能力。

当前关闭 GPU 硬件加速，是为了规避部分 Windows 显卡环境中的启动崩溃。若以后恢复，应先在目标设备验证稳定性。

## 7. 测试策略

| 层 | 重点 |
| --- | --- |
| `calendar-core` | 月底、跨年、周首日、42 格连续性、滚动窗口、节日本日判定 |
| `interaction-core` | 像素/行/页面单位、余量累计、快速滚动多行与反向滚动 |
| `holidays` | 输入校验、缓存命中、请求复用、提供方合并、失败降级与错误恢复 |
| `updater` | 开发/安装模式差异、重复手动检查、版本比较、Release 解析与失败处理 |
| 渲染模块 | 中英文词典键一致性、版本展示、公告纯文本格式化与检查结果反馈 |
| 主进程 | 安全窗口配置、启动自动检查、IPC 来源校验与实时预览刷新 |
| Electron/UI | 隐藏窗口自动验证导航、语言、周首日、滚轮、焦点、公告与更新按钮；安装替换仍需旧版安装包人工验证 |

纯逻辑优先放入可注入依赖、无需 DOM 的模块后再测试。窗口与焦点使用真实 Electron 冒烟测试；涉及旧版本替换和重启安装时，仍需在已安装版本中人工验证。

## 8. 扩展约定

### 新增界面文案或语言

在 `translations.js` 为所有语言补齐同一键值，再由控制器读取。不要在事件处理函数里散落新的用户可见字符串。中英文切换后要检查标题、图例、提示、`title` 和 `aria-label`。

### 新增设置

小型、非敏感的本机偏好可继续使用带 `vibe-calendar:` 命名空间的 `localStorage` 键。若数据结构变化，应升级键名或缓存版本，避免旧数据被错误解释。

### 新增节假日提供方

先校验并标准化远端格式，再加入合并流程，同时更新 `index.html` 的 CSP。镜像地址不能作为独立数据源参与多数判断。

### 新增系统能力

在主进程实现专用 IPC，在 Preload 暴露最小方法，并让渲染层只依赖返回的数据结构。不要暴露通用文件系统、Shell 或原始 IPC 能力。

### 新增日历事件

建议增加独立的数据层，例如 `events.js`，将持久化、查询与标准化从 `renderer.js` 分离。日期格只接收已经整理好的展示数据。
